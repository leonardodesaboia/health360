## Boundaries and plan

Consume listOpenClarificationRequests(tx, datasetId, patientId) under the existing patient lock. Its review ID/version and analysis references become server-validated expected inputs; no client-selected dataset is accepted. Unsupported named fields remain unavailable. Supported named fields reuse intake controls; requests without a target get bounded free-text answers with an explicit unknown checkbox. Duplicate targets share one bounded answer while all reviewer question text remains visible.

Question/answer snapshots use existing IntakeResponse.answers entries in a physician-clarification namespace linked to review version and proposal. Question text is system-structured metadata; responses remain PATIENT_REPORTED, including null. Profile personalHistory carries these separate sourced records so current physician readers can show them without schema or doctor changes. Existing snapshots survive subsequent clarification versions. Free text stays local and is never inferred into deterministic facts or added to model payloads.
